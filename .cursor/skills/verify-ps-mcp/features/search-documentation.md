# Docs search (`search_documentation`)

Source: `src/tools/search-documentation.ts`

Searches the PlanetScale knowledge base. This tool is itself an MCP client: it
connects over Streamable HTTP to the docs MCP server (default
`https://planetscale.com/docs/mcp`, overridable with `PLANETSCALE_DOCS_MCP_URL`),
calls the upstream search tool, and normalizes whatever shape comes back into
`{ title, url, page, snippet }` entries.

That upstream server is **generated by Mintlify** — confirmed by the
`x-matched-path: /_mintlify/mcp/[subdomain]/[transport]` response header. The
tool name, its input schema, and its response shape are all Mintlify's to
change, and it has changed them: the tool was `SearchPlanetScale` when this
wrapper was written in January 2026 and is `search_planet_scale` today.

## Reach it

A user asks a "how does PlanetScale do X" question and the agent looks it up
instead of guessing.

## Drive it

```bash
node .cursor/skills/verify-ps-mcp/drive.mjs call search_documentation \
  '{"query":"query insights bytes received"}' \
  --expect '"url":"https://planetscale.com/docs/' --label docs-search
```

Assert on a **result field**, never on `"source"` or `"total"`. Those appear in
the envelope even when zero results came back, so asserting on them passes
during a total upstream outage — that is precisely how the `SearchPlanetScale`
rename stayed invisible from roughly February to August 2026.

## Proves it works

- `total` is greater than zero and every entry carries a real `title` and a
  `url` under `https://planetscale.com/docs/`, not empty objects. An empty
  result set means normalization dropped everything — a failure even though the
  call succeeded.
- Entries carry `page` (the doc path, e.g. `vitess/monitoring/query-insights`)
  and a `snippet` of the page body. A `snippet` longer than 1500 characters is
  cut and the entry is flagged `"truncated":true`; upstream blocks run to ~10KB
  each, so most entries are truncated and that is expected.
- No `Error:` prefix in the response.

## The outage path

Upstream failure is a refusal, not an empty result set. Repoint the server at a
dead host to prove it — the harness cannot inject this, because
`StdioClientTransport` filters the child's environment to an allowlist, so the
override has to go in `.env` (back the file up and restore it; it holds the API
token):

```bash
cp .env /tmp/env.backup
sed -i '' 's|^PLANETSCALE_DOCS_MCP_URL=.*|PLANETSCALE_DOCS_MCP_URL=http://127.0.0.1:9/mcp|' .env
node .cursor/skills/verify-ps-mcp/drive.mjs call search_documentation \
  '{"query":"anything"}' \
  --expect 'Error: PlanetScale docs search is unavailable' --label docs-search-outage
cp /tmp/env.backup .env
```

## Notes

- Needs no PlanetScale credentials, which makes it the cheapest end-to-end check
  that the MCP plumbing works in a checkout with no `.env`.
- When results look wrong, read the live upstream contract before touching this
  code. It is published unauthenticated and lists every tool name, input schema
  and description:
  `curl -s https://planetscale.com/docs/.well-known/mcp/server-card.json`
- The tool takes only `query`. Upstream's schema is `{query}` with
  `additionalProperties: false`, so the old `version`, `language`,
  `api_reference_only` and `code_only` arguments were removed rather than
  quietly ignored.
- Upstream returns one `type: "text"` block per hit, shaped as `Title:`/`Link:`/
  `Page:` header lines then a `Content:` body running to the end of the block.
  `parseDocsTextBlock` reads that format and is unit-tested in
  `src/tools/search-documentation.test.ts`; the `structuredContent` and
  `resource_link` normalizers are kept as fallbacks for the next shape change.
- Upstream also exposes `query_docs_filesystem_planet_scale`, which `head`s or
  `cat`s a full page by path, and `submit_feedback`. Neither is wrapped here.
